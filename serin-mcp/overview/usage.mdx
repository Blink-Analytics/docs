Serin MCP has no task-based billing or usage dashboard for end users. What it does have is a set of hard limits baked into specific tools and into the server's own caching — this page lists them.

| Limit | Value | Enforced by |
|---|---|---|
| Published jobs per organization | 10 | `create_job` |
| Resume upload size | 10 MB | `add_prospect` / `request_resume_upload` card and link flows |
| Resume upload slot lifetime | 15 minutes, single-use | `request_resume_upload` |
| `list_tools()` cache | 5 minutes, per identity | Response-caching middleware |
| Tool-call result cache | `search_locations` only, 1 hour default | Response-caching middleware |
| Candidates per `compare_candidates` call | 2–6, same job only | `compare_candidates` |

## How caching works

Only `search_locations` is cacheable at the tool-call level — every other tool runs fresh on every call. This is deliberate: caching `get_job_details` would risk returning stale data right after an `update_job`, and caching `create_job` would risk silently skipping a second, intentionally distinct creation. `list_tools()` is cached for 5 minutes because the tool list itself rarely changes mid-session, but that cache is keyed by the caller's authenticated identity, so a role change or org switch is never served someone else's list.

## Email and outreach rate limiting

Outbound candidate emails (`send_application_email`, `invite_candidate`, `redo_interview`, `schedule_meeting`) are rate-limited per recruiter user, the same way they are from the Serin dashboard. Bulk status changes (`bulk_update_application_status`, etc.) send **no** email and aren't subject to this limit; they're safe to repeat if a call's result is ever unclear.

## What happens when a limit is hit

- **Published-job cap:** `create_job` with `job_status="published"` fails with a clear error once an organization already has 10 published jobs; drafts are unaffected.
- **Resume upload slot expired or already used:** the upload card/link returns an error; a new `request_resume_upload` call is needed.
- **Delegated-action rate limit:** the web app returns a 4xx, which **Serin MCP** relays as the specific business message (not the generic "unavailable" fallback) so the caller knows to wait rather than retry blindly.

## Frequently asked questions

**Is there a per-tool-call cost or task counter, like some MCP providers show?**
No. Serin MCP has no metering or billing surface for tool calls. The limits above are functional (data integrity, abuse prevention, upload lifetime) rather than commercial.

**Does switching organizations reset any of these limits?**
The published-jobs cap and rate limits are scoped per organization/user, not per-connection — disconnecting and reconnecting to pick a different organization doesn't reset or bypass them.
